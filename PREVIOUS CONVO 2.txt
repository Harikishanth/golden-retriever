1. NORMALIZATION (normalize.py)

What it does: Cleans messy real-world data into comparable tokens

- Accent stripping (Gúlf → gulf) - handles typos and encoding issues

2. BLOCKING (blocking.py)

What it does: Finds candidate matches (reduces 1M² comparisons to ~150 per entity)

Old approach (commit history shows this existed):
- Hash-based blocking: exact match on (country, name_normalized, city)
- Problem: Recall ceiling was only 83.4% - missed partial matches!

Current approach: BM25-style token retrieval
# Entity: "McDonald's MG Road Bengaluru"
# Creates index keys: (country='IN', type='N', token='mcdonald')
#                     (country='IN', type='A', token='mg')
#                     (country='IN', type='H', token='4292')

# Scoring for candidates:
score = Σ(IDF(shared_name_token) * 2.0) +  # Name weighted higher
        Σ(IDF(shared_addr_token) * 1.2) +   # Address weighted lower
        Σ(8.0 per matching house number)     # House# = strong signal

Why this works:
- "McDonald's" matches "McDonalds" (both index 'mcdonald')
- "M.G. Road" matches "MG Road" (both index 'mg', 'road')
- IDF weighting: rare tokens like 'starbucks' score higher than 'inc'

Smart guard: MAX_POSTING=2000 - skips super-common tokens (saves RAM, they're useless anyway)

What could be better:
- ✅ Major win: Moving from hash-blocking to token-retrieval gave ~10% recall boost!
- ⚠️ CAP=150 is hardcoded - no tuning for precision/recall tradeoff
- ✅ Country-scoped index - prevents matching US companies to Indian ones

Phase 5: Two-threshold optimization ⭐ This is the recent innovation!

The problem with single threshold:
# Entity has 50 candidates, all score 0.45 (below threshold=0.50)
# Prediction: {} (empty set = "singleton", no match found)
# But: If top score was 0.49, it was ALMOST a match!

The two-threshold strategy:
singleton_threshold = match_threshold + 0.02 to 0.15

if max(scores) < singleton_threshold:
    predict {}  # Conservative: "nothing is close enough"
else:
    predict {c for c, score in scores if score >= match_threshold}

Why this works:
- High-confidence singletons: If even the best candidate scores poorly, it's truly standalone
- Precision boost: Avoids false positives where a borderline match gets through
